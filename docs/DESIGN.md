> **Статус:** пополняющийся документ. Каждая новая секция/компонент сверяется с ним ДО

## 0. Главное правило — ОДНА система, ноль дублей

- **ONE Button.** `components/ui/Button.astro` — primary / dark / icon, **высота 48px
  (`--sp-12`) у всех вариантов, задаётся В КОМПОНЕНТЕ**. Секции НИКОГДА не объявляют
  height/padding кнопки (был форк 48 в меню/hero vs 46 в CTA-band/Compare —
  client-caught 2026-07-21). Новый вариант = правка Button.astro + карточка в UI Kit +
  строка здесь.
- **ONE heading.** `SectionHeading.astro` (Regular 40 white/80 + Bold violet accent,
  center/left). H1 героя — единственное исключение (48, свой паттерн в Hero).
- **ONE набор токенов.** Сырой hex/px, существующий в tokens.css, в компоненте = дефект.
- **Иконки — файлами** из Figma (`src/icons/**`), рендер через `<Icon>`. Инлайн-SVG запрещён.
- **Импорт из Claude Design / Figma-канваса** переносит КОМПОЗИЦИЮ и контент; хром
  (кнопки, заголовки, отступы секции, сетка) всегда пересобирается из системных
  компонентов. Кастомные кнопки/тексто-стили из канваса не переносятся.
  _(Урок 2026-07-21: из канваса уехала своя кнопка CTA и свои отступы секции — больше так не делаем.)_

## 1. Язык

Тёмный премиальный SaaS: канва `--bg` #111322, единственный акцент `--violet` #AB0DFF,
Inter Variable (self-hosted), много воздуха, мало цветов. Референс тона: semanticforce.ai.

## 2. Сетка и секции

- Контент: `--container` 1280, по центру; боковые поля `--margin-desktop`
  (fluid clamp 20→80, на 1440+ ровно 80).
- Секция: `padding: var(--sp-10) var(--margin-desktop)`; внутренний stack `gap: var(--sp-8)`.
  Между соседними секциями получается 80px (40 + 40). **Исключение:** после тяжёлого
  CTA-band верхний отступ следующей секции удваивается (`--sp-20`) → 120px воздуха
  (клиент 2026-07-21: «там очень плотно»). Сейчас это Compare.
- Голова секции (паттерн Features/Compare): `SectionHeading` слева + лид справа
  (`width: 416px; flex-shrink: 0; --fs-lead; --text-body`), `align-items: flex-end`.
- Якоря секций: `scroll-margin-top: 96px` (зона фикс-меню) — ОДНО правило в
  `global.css` на список живых якорей (`#channels, #features, #compare, #contact`),
  не по секциям.

card-sub 16 · ui 14 Medium · **caption 13/1.2 (`--fs-chip`)** · pill-label 10.
Веса 400/500/600/700. Акцентная фраза заголовка: violet, Bold (H2) / SemiBold (H1).

**Адаптив типографики — только заголовки** (клиент 2026-07-26): body-размеры
(18/16/14/13) НЕ меняются ни на одной ширине. Fluid живёт в самих токенах —
одно место, все секции консистентны:

сабы строк Compare, роль-карточки) идут на `--fs-chip` = 13, не 12.

**Исключения из пола, узаконенные клиентом (НЕ поднимать):**
`--fs-pill-label` 10px (2026-07-21, вопрос закрыт) и **12px лейблы мини-карточек
Insights-визуала** (2026-07-26: «сделай всё-таки 12») — микро-подписи внутри
иллюстраций, не подписи контента. Это микро-лейбл внутри пилла (верхняя строка ChannelPill

метка, а не подпись контента; плюс подъём раздул бы пиллы и сломал выверенную
геометрию сцены.

## 5. Секции-паттерны

- **Hero**: копи слева (549) + орбита справа (613×581, right 82); фолд-гарантия —
  см. комментарии в Hero.astro (band-gap → нырок → масштаб → fluid H1).
- **Полоса брендов**: маркиза 88px-тайлов, отступы на `--band-gap` (40→16).
- **Сцена «One platform»**: sticky-пин 220vh, скраб top-bottom; финал = полная
  композиция, пиллы не исчезают (SCROLL-SCENE-SPEC.md). **Три режима раскладки
  пиллов** (клиент 2026-07-26: «не должны зарезаться полностью»):
  ≥1440 — Figma-скэттер 1:1 (абсолютные px на стейдже 1440×650);
  947–1439 — fluid-скэттер: стейдж 100%, пиллы по `--fx`-процентам с
  самокомпенсацией (`left: fx%` на li + `translateX(-fx%)` на РЕБЁНКЕ — GSAP
  анимирует transform самого li, поэтому статичный сдвиг живёт на ребёнке);
  13 пиллов в три ступенчатых ряда над заголовком (y 36/116/196);
  ≤946 — «облако»: flex-wrap над заголовком, порядок через order;
  ≤560 — компакт-пилл (категория скрыта, диск 32) — медиа внутри самого
  ChannelPill. Инвариант, проверяемый харнесом: 13/13 пиллов видимы целиком
  и 0 пересечений с текстом на всех ширинах.
- **Features**: голова-паттерн + 3 карточки 562px + CTA-band (`--grad-cta`).
  Визуалы карточек (все — код, не картинки; файлы деталей в `src/icons/decor/**`):
  1 — орбита (25:1086); 2 — **InsightsVisual** (78:659: диски каналов → тайл →
  3 мини-карточки, `components/decor/`); 3 — **AiRepliesVisual** (78:1410:
  скелетоны отзывов → AI-тайл → ответы с чеками `--green-ok`). Приглушка 20%
  у карточек 2–3 снята (нет в дизайне 2026-07-26). Новые токены:
  `--shadow-mini-card`, `--green-ok`, `--skeleton`; лейблы мини-карточек — 13px
  (пол подписи), не фигмовские 12. Зеркальные кривые — scaleY(-1)/scale(-1,-1)
  НА МЕСТЕ (бокс уже на финальных координатах — сдвиг на -100% дублирует
  верхнюю связку, проверено).
  Механика карточки (2026-07-26): высота — `min-height` 562; орбита и фейд
  заякорены ОТ НИЗА (при 562 математика даёт фигмовские y215/y180), между
  текстом и футером — flow-резерв `.card__orbit-room` ≥236px (дизайнерская
  плотность: в самой Figma текст и messenger-пузырь расходятся на ~1px) —
  длинный текст растит карточку, а не печатается по графике. 3-up только
  ≥1200 (ниже — текст любой карточки перерастает орбиту), ≤1199 — столбик;
  CTA-band складывается ≤1150 (meta ~634px несжимаема — ниже intro красился
  ПОВЕРХ meta, client-caught).
- **Footer** (дизайн в коде; финальная композиция v3 2026-07-26 по референсу клиента —
  футер SF Group): футер = ряд БОЛЬШИХ остров-карточек на общем `.island`-примитиве
  с 4px-гэпом меню. Слева бренд-пара островов меню + карточка клейма (внутри © строка);
  в центре карточка навигации — колонки Product / Company (только живые ссылки:
  Features, Compare, внешние Semantic Force и Omnichannel HelpDesk ↗) + ряд 32px-дисков
  каналов (декор, гэп 4, без «+ more»); справа CTA-карточка: заголовок card-title +
  системная кнопка + хинт триала. Мёртвых якорей нет — новая секция «зарабатывает»
  свою ссылку, когда выходит; Privacy/Terms/En вернутся со страницами. Брейкпоинты:
  3 карточки в ряд только ≥1440 (полный контейнер 1280), 761–1439 — 2 колонки + CTA
  во всю ширину, ≤760 — столбик. Колонки Product/Company — max-content рядом

  (клиент 2026-07-26). Меню (Nav): прячется на скролле вниз, возвращается на
  малейшем скролле вверх; поля 16→8 в полосе 941–955, бургер ≤940.
  _(v2 «каждая ссылка — микроплитка» отклонена клиентом в тот же день.)_
- **Compare** (дизайн: Claude Design «Comparison Table.html», 2026-07-21):
  цены $-глифами в шапках колонок (заполненные + `.off` 35%), violet-зебра чётных
  строк, RA-колонка `--surface-pill-social` + границы `--border-strong` +
  скругления r-md сверху/снизу, числа `--fs-card-title` SemiBold. Ячейки — только
  метки/числа/$-глифы, без бейджей-квалификаторов (убраны 2026-07-21). Шапка
  таблицы sticky (докается под меню на 96px): ячейки полностью непрозрачны +
  «козырёк» ::before закрывает щель меню — строки скроллятся в своём фрейме и
  не всплывают над шапкой. Козырёк армится ТОЛЬКО в докнутом состоянии
  (IO-сентинел, `.is-docked`) — постоянный козырёк резал заголовок секции в
  потоке (client-caught). ≤946 — static. Честность: кресты и в нашей колонке.

## 6. Эффекты и моушн

- Глоу: стопки пре-блюренных квадратов (`--glow-*`); анимировать opacity/scale, не blur.
- Тени тайлов: `--shadow-app-tile(-hero)` (5 слоёв).
- Моушн: transform/opacity only; `--ease-out`, `--dur-fast/normal`; каждая анимация
  уважает `prefers-reduced-motion` (статика = дизайн-состояние).

## 7. Адаптив (деградация без мобильных фреймов)

≤955 — меню уходит в бургер (своя мера, см. Nav.astro). ≤946 (остальной сайт):
hero в одну колонку (орбита-шоупис ниже копи), головы секций в стек,
карточки Features в столбик, CTA-band в колонку. ≤760: компакция таблиц/чипов.
Механика фолда — только desktop/tablet (≥947).

## 8. Процесс пополнения

1. Новая секция → сверка с этим доком и `/preview/uikit` до вёрстки.
2. Новый компонент/вариант → сначала карточка в UI Kit + строка в §4/§5, потом секция.
3. Импорт из Figma/Claude Design → композиция из канваса, хром из системы (§0).
4. Прогон QA-харнеса (audit/) после каждой вёрстки: overflow/console = 0.
